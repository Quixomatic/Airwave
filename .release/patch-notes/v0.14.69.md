## Highlights

Airwave now has a public integration API. This release adds a documented, API-key-authenticated REST surface at
`/api/public/v1` so you can read your server's live data (the guide, channels, packages, and who's watching)
from Home Assistant, Tidbyt, a Tauri app, or anything that speaks HTTP. It comes with an interactive API
reference and integration guides on getairwave.tv. Each install also gets an editable display name and a
discovery endpoint so a client can identify a specific server.

## New Features

- **Public integration API (`/api/public/v1`).** A new, separate REST surface for outside integrations (Home
  Assistant, Tidbyt, Tauri, n8n, generic REST), kept apart from Airwave's internal TV-client and admin APIs so
  its contract can stay stable for third parties. Authenticate with the existing `airwave_` API key (Settings,
  API Keys, the same key the MCP server uses), sent as either `X-API-Key` or `Authorization: Bearer`. It
  publishes a first-party OpenAPI 3.1 spec at `/api/public/v1/openapi.json` with an interactive Scalar reference
  at `/api/public/v1/docs`. Every endpoint is read-only and scoped to what the key's user may access:
  - **Server:** `GET /status` (product, version, install id, display name, uptime, current time, and live
    counts of channels, packages, and active viewers) and `GET /capabilities` (API version, optional server
    features, and whether webhooks or the SSE stream are available).
  - **Channels:** `GET /channels`, `GET /channels/{id}`, `GET /channels/by-number/{number}`,
    `GET /channels/{id}/now` (now and next with the live offset), and `GET /channels/{id}/schedule` (upcoming
    programs). Add `?include=definition` to also get a channel's authoring internals.
  - **Packages:** `GET /packages` (each with an accessible channel count) and `GET /packages/{id}` (the package
    plus its channels).
  - **Guide / EPG:** `GET /guide` (the now/next grid across accessible channels, with `?forwardMinutes` /
    `?backMinutes`) and `GET /guide/now` (a compact one row per channel, small enough for a Tidbyt).
  - **Now watching:** `GET /sessions` (active watch sessions), `GET /sessions/count` (the cheapest "is anyone
    watching" sensor), and `GET /now-playing` (a compact view).
- **Editable server display name.** Each install now has a display name (for example
  "Sapphire Vole - Airwave Server"), auto-generated on first run and editable anytime under Settings, General.
  It appears in `/api/identity` as `name` so a client can label a discovered server.
- **Public `/api/identity` discovery endpoint.** Returns `{ product, version, instanceId, name }` so a client
  can confirm a server is genuinely Airwave and recognize a specific install. `instanceId` is a stable
  per-install id, used only for local discovery and never phoned home. `/api/health` stays the bare liveness
  probe.

## Improvements

- **Refreshed admin login page.** A faded grid pattern plus a subtle cool aurora glow along the bottom edge,
  both layered over the app's noise texture in light and dark. The logo lockup moved inside the card, the title
  and subtitle sizing was tightened, and the card shadow was softened.

## Docs

- **API Reference on getairwave.tv.** A new API Reference section renders the public API's OpenAPI 3.1 spec with
  an interactive playground, grouped by tag, reachable from the documentation sidebar's root switcher. The
  playground's "Try it" targets a spec-driven mock, so it returns example data with no real Airwave server; a
  second server entry points at a self-hosted address so you can switch the base URL and use your own key.
- **Integration recipes.** A new "Extend Airwave" documentation group with quick starts for Generic REST
  (curl), Home Assistant (REST sensors), and Tidbyt (a pixlet app), plus an Integrations overview.

## Migration

- Two nullable columns were added to the app settings (`instanceId`, `serverName`). They apply automatically on
  the server's pre-deploy database migration; no action is needed.
