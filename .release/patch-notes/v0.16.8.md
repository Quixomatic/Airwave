## Highlights

A security-focused release: three vulnerabilities (two High, one Medium), all privately reported by @cashcon57, are fixed, along with a long-standing Apple TV annoyance.

- Closed an unauthenticated path traversal in the `/img` artwork proxy that could reach your Plex server with the admin token.
- Closed an open redirect in the Plex sign-in flow, and took the API key out of the live-events (SSE) URL (now a header or a single-use ticket).
- Apple TV now keeps its server and session across a reboot instead of dropping back to setup.

## Security

Three vulnerabilities, privately reported by @cashcon57 and fixed in this release. Advisories: GHSA-vc4j-53mw-85mx, GHSA-6p5v-m89f-x7hg, GHSA-fjx9-jwmr-2r58.

- **`/img` artwork proxy path traversal (High).** The proxy checked only that the caller's path started with `/library` or `/photo`, but `fetch` resolved `..` / `%2e%2e` afterward, so a crafted `?path=` could reach arbitrary admin-token Plex endpoints (sessions, preferences, library/account) and the `/photo` transcoder's `url=` (SSRF), unauthenticated and reachable over Remote Access. Artwork paths are now resolved first and must stay on the same Plex server under `/library/`, with no traversal, query, or host change; `w`/`h` are clamped; the public artwork rating key is constrained to digits.
- **Plex sign-in open redirect (High).** `/api/plex/authorize` built Plex's `forwardUrl` from an unvalidated `redirect_uri`, so a crafted sign-in link could bounce the Plex pin to an attacker's URL after the victim approved on plex.tv. The `redirect_uri` is now accepted only when its path is the Plex callback and its origin is trusted (the configured server URL / CORS origins, or the forwarded host over the Airwave Cloud tunnel), so the pin can only ever return to your own callback. Every real sign-in path (localhost, reverse proxy, LAN, tunnel) still works.
- **API key could leak from the live-events (SSE) URL (Medium).** The events endpoint accepted the key as `?api_key=`, which the request logger wrote to stdout and which also lands in proxy/CDN logs and browser history. Fixed in three steps: the request logger now redacts secret query values; a single-use, ~60s connection ticket (`POST /api/public/v1/events/ticket`, then `?ticket=`) lets a browser `EventSource` authenticate without a key in the URL; and `?api_key=` was removed from the URL entirely, leaving header or ticket only.

## Fixes

- **Apple TV keeps its server and session across a reboot.** On tvOS the server URL, token, and session were stored in AsyncStorage, which the OS purges when storage runs low, so an Apple TV forgot its server after a restart and dropped back to onboarding. Those values now live in UserDefaults (the one durable tvOS store), so they survive a reboot. No new native module; iPad, iPhone, and Android are unchanged. A one-time migration carries over any values not already purged; an Apple TV whose cache was already cleared re-onboards once.

## Breaking / Migration

- **The live-events SSE endpoint no longer accepts `?api_key=`.** A browser `EventSource` that used it must switch to the ticket flow: `POST /api/public/v1/events/ticket` with the key in the `X-API-Key` header, then open `GET /api/public/v1/events?ticket=<ticket>` (mint a fresh ticket per reconnect, since each is single-use). Fetch and header clients (Tauri, dashboards, Home Assistant) are unaffected.

## Docs

- **Live events (SSE) integration guide updated** for the new auth model: the `X-API-Key` header for fetch-based clients, a single-use ticket for browser `EventSource`, and no API key in the URL.

## Under the hood

Typecheck and developer-tooling work. No runtime or user-facing behavior change.

- **`pnpm check-fast`**: a `bun check` (TypeScript 7) typecheck across the whole monorepo, roughly 6x faster than tsc, running alongside the existing tsc `check-types`. Requires Bun 1.4.3+.
- **Type-correctness pass**: fixed latent type errors in shipped code (the GUID remap resolver, the remote-access relay buffers, a dead UI prop, a workflow-SDK type skew) and held the server's diagnostic scripts to the project's strict typing.
- **Removed vestigial TypeScript declaration-emit config** from the server and internal packages (they are consumed as source), clearing ~133 phantom composite/declaration errors so the repo type-checks cleanly.
- **apps/desktop electrobun types**: resolved `electrobun` imports to the Hutch devkit so the desktop app type-checks cleanly.
